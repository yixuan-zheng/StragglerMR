# Architecture and failure contract

One coordinator schedules a fixed word-count operation over immutable input snapshots through synchronous gRPC Submit/Inspect calls. Separate local worker processes use fixed thread pools with bounded admission. Shared storage is required; there is no RPC file transport or distributed shuffle. One coordinator exclusively schedules a worker set; concurrent coordinators sharing workers are unsupported.

Words are maximal ASCII letter runs folded to lowercase; every other byte is a delimiter. Each input file is one logical task. Output is sorted word/tab/unsigned-count/newline. Empty files/results are valid. The independent Python oracle uses byte regexes and Counter, rather than the C++ scanner/map. Limits remain 1–1000 files, at most 4 MiB/file and 64 MiB/job; 1–16 workers with 1–16 slots each; at most 10,000 retained attempt records per worker. Callers must not mutate inputs during initial snapshot copying; snapshots stay unchanged afterward.

Submit is idempotent for an identical job/attempt request, including after completion; conflicting identity reuse is rejected. Queued and executing work share physical capacity. A failed Inspect or changed worker instance quarantines that endpoint for the job, with no restart/rejoin. RPC deadlines and finite job/task budgets turn errors into retries or explicit failure. A timeout retires eligibility without claiming the remote computation stopped. A result observed before the control-loop expiry sweep may be accepted; timing bounds are observations, not hard real-time guarantees.

Each attempt writes a separate workspace. Terminal metadata binds artifact byte length and SHA-256. The coordinator opens once, checks those values plus job/task/attempt identity, sorted unique ASCII keys and positive bounded counts, then regenerates its own accepted artifact from the validated in-memory values. Aggregation uses those same values, never a reopened worker path. A late original or backup cannot change already accepted bytes through its designated workspace. Same-user hostile processes could write directly into other directories and are outside the trust model.

The final result is staged, flushed/closed and atomically renamed. This provides local visibility, not crash durability: there is no fsync-based recovery, coordinator restart, storage/machine failure guarantee or exactly-once external side-effect API. SHA-256 detects mutation against trusted completion metadata, not malicious computation. The serial oracle validates semantic results in tests.

The [frozen policy](speculative-policy.md) permits one proactive backup on another worker; one valid candidate is accepted, and later/retired candidates are rejected. Physical accounting includes live losers and expired work until terminal confirmation. Unknown speculative attempts on quarantined endpoints retain their global-cap charge conservatively. This can suppress useful speculation or lead to explicit deadline failure; it does not authorize excess admission.

No loser cancellation is implemented. Optional bounded drain observes late results after publication; normal launchers own worker shutdown, terminate/wait for children and clean retained workspaces. Coordinator-only work statistics are lower bounds when executions remain unresolved; the original performance study reconciled local terminal/crash timings separately.
